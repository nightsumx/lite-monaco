    You delete more than you add.

    No workers to configure, no highlighter to wire up. With shiki installed, languages and themes are colored lazily. Code under monaco.editor and monaco.languages stays as it is.

    05Caveatsthe worst thing a replacement can do is look the same

    What is known to differ, in the open.

    • KNOWN-01A different input layer

      Monaco uses a hidden textarea / EditContext; lite-monaco uses contenteditable. Screen-reader roles and aria attributes match, the accessibility tree structure cannot. Not yet tested with VoiceOver, NVDA or JAWS.

    • KNOWN-02IME composition differs

      Monaco updates the model on every composition update; lite-monaco writes once on commit. The committed result is the same. Simulated over CDP, not verified with a real IME on a real device.

    • KNOWN-03Not the VS Code platform

      No editor.createWebWorker, no languages.*.getWorker, no multi-file diff editor, no accessibilityPageSize paging.

    • KNOWN-04Browser coverage

      Playwright builds of Chromium, Firefox and WebKit all run. Real Safari and real touch screens (selection handles, soft keyboards) are not verified.

    • KNOWN-05TypeScript smarts are a separate install

      Completion, hover, diagnostics and go-to-definition come from the optional typescript dependency. This page does not load it, so TS here is highlighting and editing only.
